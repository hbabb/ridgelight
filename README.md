# Ridgelight

My personal website: projects, blog posts, and resume.

Built with Go, templ, Alpine.js, and plain CSS. Content lives in Markdown and YAML files in this repo. No database.

> **Status:** Planned. Not started yet.

---

## Sections

- **Projects**, grouped by category:
  - GIS
  - CLI
  - Web / general
- **Blog**: posts written as Markdown files
- **Resume**: rendered from `resume.yaml`, with a PDF download generated by [resumekiln](https://github.com/hbabb/resumekiln)

---

## Stack

| Part          | Tool                                         | Role                                                         |
| ------------- | -------------------------------------------- | ------------------------------------------------------------ |
| Server        | Go (`net/http`)                              | Serves every page; one binary                                |
| Templates     | [templ](https://templ.guide)                 | Type-checked HTML components compiled to Go                  |
| Interactivity | [Alpine.js](https://alpinejs.dev)            | Small client-side behavior (menus, filters)                  |
| Partial pages | [Alpine AJAX](https://alpine-ajax.js.org)    | Alpine plugin; updates parts of a page from server responses |
| Styling       | Plain CSS                                    | No CSS framework, no build step                              |
| Markdown      | [goldmark](https://github.com/yuin/goldmark) | Renders blog posts and project write-ups                     |
| Resume data   | `resume.yaml`                                | JSON Resume structure, read by Ridgelight's own structs      |
| Files         | Go `embed`                                   | Content and static files are baked into the binary           |

## Content

### Blog post

`content/posts/<slug>.md`

```markdown
---
title: "Post title"
date: 2026-10-24
tags: [go, gis]
draft: false
---

Post body in Markdown.
```

### Project

`content/projects/<slug>.md`

```markdown
---
title: "Project name"
category: gis # gis | cli | web
repo: https://github.com/hbabb/<repo>
tags: [go, postgis]
---

Project write-up in Markdown.
```

The projects page groups entries by `category`. Moving a project to another group only means changing that field.

### Resume

1. Edit `content/resume.yaml`.
2. Generate the PDF locally with resumekiln.
3. Copy the new PDF to `static/resume.pdf`.
4. Commit through a pull request.

The resume page and the PDF should be regenerated together so they don't drift apart.

## Development

### Requirements

- **Go 1.27.3.** If your installed Go is older, the `go` command downloads the version in `go.mod` automatically.
- **golangci-lint:** `sudo pacman -S golangci-lint`
- **Just:** `sudo pacman -S just`

templ and govulncheck are tracked as project tools in `go.mod` (Go 1.24+ `tool` directive), so their versions are pinned per project and Dependabot keeps them updated. No separate install is needed.

### Tasks

Run `just` to list every task.

| Task              | What it does                                                     |
| ----------------- | ---------------------------------------------------------------- |
| `just templ-fmt`  | Formats `.templ` files                                           |
| `just generate`   | Generates Go code from `.templ` files                            |
| `just fmt`        | Formats Go files (gofumpt and goimports)                         |
| `just lint`       | Runs the linters in `.golangci.yml`                              |
| `just vuln`       | Checks for known vulnerabilities with govulncheck                |
| `just test`       | Runs the tests                                                   |
| `just tidy`       | Adds missing and removes unused modules in `go.mod` and `go.sum` |
| `just run`        | Runs the server at http://localhost:8080                         |
| `just pre-commit` | Runs tidy, templ-fmt, generate, fmt, lint, vuln, and test        |

### Before each commit

```sh
just pre-commit
```

The generated `*_templ.go` files are committed, so a fresh clone builds without running templ first. `just pre-commit` regenerates them, so they stay in sync with the `.templ` files.

## Deployment

Hosted on a DigitalOcean Droplet.

1. **Pull request** → `ci.yml` checks that generated templ files are current and formatted, runs golangci-lint and govulncheck, and runs the tests. Nothing deploys.
2. **Merge to `main`** → `deploy.yml` builds the binary in GitHub Actions (never on the Droplet).
3. The new version starts in the idle container (blue or green), managed by Podman Quadlet.
4. After a health check passes, Caddy is switched to the new container and reloaded.
5. The previous container stays available for an instant rollback.

Direct pushes to `main` are blocked by branch protection; changes arrive only through pull requests with passing checks.
